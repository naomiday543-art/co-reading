# 總設想：研究進度圖（一個方向一張）

**日期**：2026-09-18　**狀態**：設想稿，待她點頭。點頭後才拆工單；第 2 步的細工單要等精煉修通、看到真 claims 再寫。
**跨兩個 repo**：co-reading（臉：觸發精煉、畫圖）＋ research-gateway（心：claims 圖、精煉引擎）。兩邊照舊各自獨立，契約解耦，不合併。

---

## 〇、一句話

把 gateway 已經在存的「研究狀態」（假設、發現、決定、下一步、矛盾、被推翻的路）畫出來：**一個研究方向一張圖，方向底下所有論文的狀態合在一起**，回退過的路看得見。

## 一、她要什麼（原話，立此存照）

- 「這個進度我能看得到嗎？我想做成像思維導圖那樣子的」
- 「如果我的進度突然回退呢？就是發現錯誤，返回到上一個節點？」
- 「一個研究方向底下所有論文合成一張」
- 不是設定頁那棵方向×知識樹；不是單篇一張。
- 參考別人的不只是圖，是「這整個的骨架」。

## 二、現況：料是現成的，圖和方向線還沒有

| 已經有 | 還沒有 |
|---|---|
| gateway 精煉引擎：九種 claim、五種關係（支持／部分支持／矛盾／細化／回答）、六種操作（新增／更新／合併／取代／標衝突／忽略） | 精煉從沒成功過（供應商欠費）→ **步驟 0 正在修**，改走 OpenCode |
| 取代不刪：舊 claim 標 superseded、記被誰取代，另有 append-only 修訂史 | 方向級的線：契約留了 `topic:<slug>` 這種鍵，但 co-reading 只會送 `paper:<id>` |
| 每條 claim 帶出身（論文報告／她的假設／AI 推導…）與來源論文 | 任何圖形視覺；co-reading 前端零圖形庫 |
| 查詢口 `GET /claims?session_key=`：回該線所有現行 claims 與關係 | 這個口不回「被取代的歷史」與「每條出自哪篇」——畫圖前要補 |
| co-reading 續窗面板（六段清單＋溯源視窗） | 她 10 篇論文只有 2 篇掛在方向上 |

生產 gateway 目前 claims 表是 **0 筆**。這是好消息：線怎麼切現在定，沒有舊資料要遷。

## 三、資料怎麼流：一個方向一條線，一次餵一篇

**做法**：頂層方向節點＝一條研究線，鍵是 `topic:<方向節點 id>`。她在某篇論文按「精煉」時，co-reading 把**那一篇**的新對話送進**方向線**（不是單篇線），並附上這篇的 paper_id。

**跨論文的邊怎麼長出來**：精煉 prompt 本來就會把該線「所有現行 claims」列給模型看。第二篇進來時，模型看得到第一篇留下的 claims，就能對它們下「矛盾」「支持」「取代」。所以不用把十篇對話串成一大包（那會爆上下文，膽固醇那一篇單獨就 38k token），也不用發明新的精煉模式——**同一個引擎、同一個 prompt，只是換鍵**。

**增量**：每篇論文各記一個「精煉到第幾則」的游標，存在 co-reading 本地。gateway 那邊靠輸入指紋做冪等，重按不重算。

**沒掛方向的論文**：照舊走單篇線，續窗面板照常可用，只是不進任何方向圖。掛上方向後，對它重新精煉一次就併進去。

**子方向**：一張圖只到頂層方向。樹裡的子節點當圖上的篩選條件，不另開線。

**要實彈驗證的假設**（步驟 1 的驗收重點）：第二篇進來時，模型真的會對第一篇的 claims 下跨篇關係，而不是各說各話。不成立的話，退路是在精煉 prompt 補一句明示。

## 四、圖長什麼樣

- **根**：方向名。第一層：這個方向的「研究問題」。往外：假設 → 發現／證據 → 決定 → 下一步。開放問題掛在它所屬的問題底下。
- **橫線是靈魂**：「矛盾」是橫跨兩枝的虛線，不能為了樹形砍掉。gateway 的規矩是證據衝突永遠不被新結論蓋掉，圖上也一樣。
- **回退看得見**：被取代的節點**預設不畫**（畫灰會佔位置、把佈局撐歪），右上一個開關「顯示走過的路」；打開後舊節點以淡色出現，連一條「被誰取代」的線，點開讀取代理由。
- **出身用顏色**：論文報告／她的假設／AI 推導，沿用續窗面板現有的標籤配色。
- **哪篇論文**：節點角標顯示來源論文；可按論文篩選、高亮。
- **點節點**：開現有的溯源視窗（來源、關係），並可「去對話」跳回那一則——沿用工單 18 的跳轉。
- **佈局兩趟走**（調研報告的頭號警告）：先只拿「支持／細化／回答」挑一棵生成樹算座標；一個節點多個父時挑一個當結構父，其餘降級成橫線；「矛盾」絕不參與佈局，事後照座標疊上去。樹演算法遇到多父、多根、有環會直接拋錯，她的資料三種都會踩。
- **繁中換行**：節點用真 HTML 疊在 SVG 邊層上，讓瀏覽器自己排版；中英混排（「Py-GC/MS 在富脂基質…」）要設 `overflow-wrap:anywhere` 與 `line-break:strict`，否則長拉丁詞撐爆節點框。這是第 2 步真正的工作量，不是佈局。

## 五、路線：四步，每步買到什麼

| 步 | 做什麼 | 買到什麼 | 量級 | 前置 |
|---|---|---|---|---|
| **0** | 精煉線改走 OpenCode（gateway 補標頭；工單已開、實作中） | 精煉第一次能跑；續窗面板第一次有內容 | 半天＋部署 | 她在 VPS `.env` 加四行 |
| **1** | 方向線：co-reading 精煉目標改成方向鍵、每篇游標、沒掛方向退回單篇線 | 續窗變成方向級；跨篇矛盾開始出現；**她第一次看到真 claims** | 約 1 天 | 步驟 0 上生產；她把論文掛到方向 |
| **2** | 靜態圖：新頁「研究進度」、兩趟佈局、矛盾虛線、走過的路開關、點節點溯源。只裝 `d3-hierarchy`（5.5 KB），其餘手寫 | 她要的那張圖 | 約 2 天 | 步驟 1 跑過至少 2 篇；gateway `/claims` 補回「被取代歷史＋來源論文」 |
| **3** | 互動版：拖曳、時間軸滑桿看回退、局部聚焦視圖；引 React Flow。gateway 補雙時間軸與「重複又取代」 | 常看才值得 | 另議 | 她用了步驟 2 一陣子、說不夠 |

**每一步做完都可以停。** 步驟 1 做完如果清單已經夠用，圖可以不畫。

## 六、借了誰的什麼（調研結論：整套骨架沒人做過，借的全是想法）

調研全文：`research-map-skeleton-survey-20260918.md`（41 KB，日期與授權皆當日親查）。結論是沒有任何開源專案同時做到「抽取 → 有版本的學術主張圖 → 注入下一次對話 → 視覺化」。我們的資料模型比掃到的每一個都更貼研究本身，不推倒重來。

| 借誰 | 借什麼 | 用在哪一步 |
|---|---|---|
| Graphiti（Apache-2.0） | **雙時間軸**：分開記「文獻上何時成立」與「我們何時知道」。一篇 2023 年的論文她 2026 年才讀到，推翻的是 2019 年的結論——現在只有一軸，時間軸會把兩種順序混成一條 | 3 |
| Graphiti | 去重 prompt 允許「**同時是重複又是取代**」；我們六選一互斥，表達不出來，是精煉的具體缺口 | 3 |
| AI-Scientist-v2（⚠️授權非開源，只借架構不抄碼） | 後端算座標、前端笨渲染 | 2 先在前端算，資料大了再搬 |
| Wikidata | 被推翻的東西**預設過濾、不是預設畫灰**；取代必須附理由 | 2 |
| ExcaliBrain（MIT） | 退路：全域圖畫不漂亮就改「以一個節點為中心的局部視圖」，矛盾固定擺右側，永不跟主幹打架 | 3 |
| Discourse Graphs（Apache-2.0） | 產品語言：把觀察和詮釋分開，不把分歧壓平 | 全程 |

**授權地雷（不碰）**：tldraw（上生產要買授權，co-reading 要發安裝包）、elkjs（EPL/GPL＋423 KB）、AI-Scientist-v2 代碼、個人知識庫類清一色 AGPL。`mind-elixir` 的 npm `latest` 指向 prerelease。

## 七、紅線

1. **圖是唯讀的。** 節點是 gateway 抽出來的，圖上不能手改、不能拖出新關係。要改狀態，回對話裡說，下次精煉會收。（這也是不用 mind-elixir 的原因：它是編輯器。）
2. **gateway 是唯一事實源。** co-reading 只快取、只渲染，不另存一份 claims。
3. **矛盾邊永不因佈局或美觀被省略。**
4. **不自動精煉。** 8/29 她拍板手動觸發；方向圖不改這條。
5. 洞察庫不動。洞察記「學到什麼」，研究進度記「走到哪」，兩個系統分工照舊；`progress` 不入洞察庫維持契約原樣。
6. 兩個 repo 不合併；co-reading 出海 payload 不加欄位。

## 九、待她拍板（三題，都有推薦）

1. **圖住哪**：推薦側欄新開一頁「研究進度」，先選方向再看圖。不塞在單篇討論頁的續窗面板裡（那裡留著清單，範圍縮成「這篇貢獻的部分」）。
2. **還沒精煉的論文**：方向圖只畫得出精煉過的論文。推薦在圖頁頂顯示「這個方向還有 N 篇沒精煉」，附一顆「逐篇精煉」按鈕，她按了才跑（會花 OpenCode 額度，一篇約一到三分鐘）。
3. **游標與重來**：某篇對話被她編輯或重生過，游標之前的內容變了。推薦不追溯，只在那篇旁邊給一顆「這篇重新精煉」，由她決定要不要重跑；重跑產生的變化走正常的取代流程，舊節點進「走過的路」。

## 十、我會自己定、不用她拍的技術題

- 方向鍵用節點 id（契約允許的字元集 nanoid 剛好符合），方向改名不影響線。
- 每篇游標存 co-reading 本地新表；gateway 不感知。
- `/claims` 補兩個欄位（來源論文、被取代歷史開關）＝ gateway 小工單，排在步驟 2 前。
- 步驟 0 之後另開的小單「精煉錯誤訊息透明化」（402／401 分家）不在這條線上，但建議在步驟 1 前做掉，不然下次壞了又要派人查。
