# 工單 25：閱讀頁把垂直空間還給 PDF 與討論

**日期**：2026-09-21　**狀態**：她用了工單 24 之後當場回饋（附截圖），直接做；✅ 已實作＋親驗
**基線**：`main` @ `ec2c9e9`　**分支**：`feat/wo25-reading-vertical-space`（worktree——她的 `node --watch`／vite 掛在主樹）
**性質**：純前端三個檔，兩件事其實是同一個病：**閱讀頁的垂直空間被吃掉了**。後端零改動。

## 一、她要什麼
> 「下面"上傳PDF"這個橫欄太大了，能否做得小一點？這樣多留空間給討論和PDF，並且左邊窗口中左右滑動的劃塊是沒有的，我只能用觸控板，有點不方便」

截圖：分欄模式、PDF 放大到 163%、視窗不高。

## 二、診斷
1. **上傳橫欄**：`UploadZone` 由 `App.jsx` 全域渲染在每一頁底部，`m-6 mt-0` ＋ 內層 `py-4` ≈ 57px ＋ 21px 下邊距。論文庫頁它是主要動作、靶該大；但在論文詳情頁它是次要動作，卻跟論文庫一樣高。
2. **「沒有左右滑塊」不是沒有，是被擠到畫面外**：PDF 是瀏覽器內建檢視器的 iframe，捲軸是檢視器自己畫在 iframe **底邊／右邊**的。`FullTextView` 把 iframe 寫死 `minHeight: 600px`——可用高度不到 600 時（視窗矮、或瀏覽器縮放調大），iframe 比容器還高，底部溢出到外層 `overflow-y-auto` 的捲動區下面，水平捲軸跟著一起不見；她得先把外層往下捲才看得到它，所以實際上只能靠觸控板橫移。
   - 同頁對照實測（視窗 1333×653）：`minHeight 600` → iframe 高 600、框底超出捲動區 **163px**、外層多一條垂直捲軸；改後 → iframe 高 417、框底在捲動區內、外層不需要捲軸。

## 三、改動
- `frontend/src/components/UploadZone.jsx`：新 `compact` prop（預設 `false`）。細條版＝`mx-6 mb-2`、內層 `py-1`、字 12px、圖示 14px、方向下拉同步縮小。功能（拖放／點擊／批次／選方向／上傳進度）一樣不少。
- `frontend/src/App.jsx`：`<UploadZone compact={page !== 'library'} />`——**只有論文庫頁是大靶**，論文詳情／對比／研究進度／洞察都用細條。
- `frontend/src/components/FullTextView.jsx`：`minHeight: '600px'` → 常數 `PDF_FRAME_MIN_HEIGHT = 240`（正文與 SI 兩個 iframe 共用）。只保一個不至於塌掉的下限，其餘交給既有的 `flex-1` 貼合可用高度。視窗夠高時行為與原本相同（本來就是 `flex-1` 撐滿）。

## 四、紅線
後端、資料、`dist/` 不動；論文庫頁的上傳區外觀不變；閱讀模式（本來就不顯示上傳區）不變；手機版 `.cr-uploadzone { margin-bottom: 76px }` 那條規則不動。

## 附錄 A：合入後她回報「現在有兩個滑塊」＋記住分隔線位置（2026-09-21 傍晚）

**合入**：17:20 `--no-ff` 合入 main `8e275bd`（純前端，後端 PID 沒變；in-flight 閘門單獨查過）。

**她的截圖**：PDF 框底出現**兩條**橫向滑塊——上面一條深色（拖把約半寬）、下面一條淺色（拖把約九成寬、橫跨整個框）。

**判讀（我的判斷，不是親驗——我這邊的檢視器不是她那一個）**
- 上面那條＝PDF 檢視器「頁面內容」的橫向捲軸：她放大到 168%，頁面比框寬。這就是她要的那條，工單 25 把它從畫面外救回來了。
- 下面那條＝**檢視器整個頁面**的橫向捲軸：她的瀏覽器 PDF 檢視器工具列項目多（有 Summarize 等），左欄約 700px 時工具列放不下——截圖裡工具列最右只到下載鈕，標準配置後面還有列印與「⋮」，被裁掉了。拖把九成寬 ⇒ 只溢出約一成（≈77 css px ≈ 兩顆按鈕），數字對得上。它以前也在，只是跟上面那條一起被擠在畫面外。
- 佐證：在我這邊的 Chromium 檢視器用 360px／900px 兩個 iframe 對照，工具列會自動收合、兩種寬度都只有一條——所以第二條不是我們的版面造成的，是她那個檢視器工具列不收合。**檢視器是瀏覽器的，裡面的 DOM／CSS 我們碰不到**（`#toolbar=0` 可以整條藏掉，但她在用縮放與頁碼，不替她拿掉）。
- 解法在我們這邊只有一個：**讓左欄寬到工具列放得下**，第二條自然消失（順便再還她一條捲軸的高度）。

**改動**：分隔線位置原本是 `useState(50)`——每次進論文都回到 50%，她得每次重拖。改成記在 `localStorage`（key `co-reading:detail-split`）：初值 `loadSplit()`（不在 30–70 或讀不到就回 50）、**放手時**才存（不在每個 mousemove 寫）、存一位小數。只動 `frontend/src/pages/PaperDetail.jsx`。
**驗證**：631/631；build 到暫存綠；副本＋`:3474`：拖到上限 → `style.width=70%`、`localStorage="70"`；重新整理仍 70%；塞壞值 `999` → 回 50%。
**已知**：上限仍是 70%（既有夾限，百分比以整個視窗寬為基準）；還要更寬就開閱讀模式（左欄 100%）。
